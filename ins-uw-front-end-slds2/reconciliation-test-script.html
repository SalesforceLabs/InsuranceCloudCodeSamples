Data Reconciliation Test Script

A focused, task-based script for validating the manual data-reconciliation experience in the Agentic Insurance Underwriting Workbench — selecting sources for conflicting values, mapping attributes, overriding and manually entering values, and resolving duplicate submission lines.

Study type: Unmoderated usability test Duration: ~15–20 min Working record: Location 1 – Chicago Warehouse Line of Business: Commercial Property

Researcher setup

Do not show this section to the participant.

  • Start URL / start point: the Commercial Property submission line page for the NexGen Biologics submission, at enrichment Step 1. Confirm the left tree shows Location 1 – Chicago Warehouse and that the Resolve Attribute Mapping and Resolve Duplicate Submission Lines cards are visible at the top.
  • Reset between sessions: clear the site's local and session storage — reconciliation state (selected sources, overrides, manual values, resolved duplicates) persists in the browser.
  • Task success: completion of the action + a self-reported ease rating (1–5, where 5 = very easy) per task.
  • Think-aloud: remind participants at the start and once mid-session if they go quiet.
Note on the duplicate task. The flagged duplicate in Commercial Property is the San Jose location pair (Location 3A / 3B), not Chicago Warehouse — Chicago has attribute conflicts but no duplicate. Tasks 1–7 use Chicago Warehouse; Task 8 uses whichever group the Resolve Duplicates carousel surfaces. This is intentional and does not need to be explained to the participant.

Introduction (read to / shown to the participant)

Scenario Thanks for helping us test an underwriting workbench prototype. You're an underwriter reviewing a new commercial property submission. The system has already pulled data from the broker's documents and email — but some values conflict across sources, some data hasn't been matched to a field yet, and some records look like duplicates. Your job is to clean this up so the submission is ready to quote.

Please think aloud the whole time — tell us what you see, what you expect to happen, and anything that's confusing. There are no wrong answers; we're testing the product, not you.

Tasks

Present one task at a time. Each includes a prompt, an optional hint (for the researcher only — reveal only if the participant is fully stuck), and follow-up questions.

Task 0Orientation & first impressions
Say to participant Before clicking anything, take a moment to study this screen. Walking through it out loud, point to each area you notice and tell us what you think it is and what it's there to help you do. Then describe, in your own words, what you believe this whole screen is for and what it's asking you to accomplish.
Follow-up questions
  • What do you think a "submission line" represents? What kinds of things do you expect to find in that left-hand list?
  • What do you think the two cards at the top — "Resolve Attribute Mapping" and "Resolve Duplicate Submission Lines" — are for?
Task 1Explore a submission line
Say to participant Open Location 1 – Chicago Warehouse from the list on the left. Take your time looking at what opens up, and click through each of the tabs in the detail view — talk us through what each one shows: what information is there, how it's organized, and anything that stands out or seems to need your attention. Don't change anything yet — just describe what you see on each tab and what you think you could do here.
Follow-up questions
  • What is this view telling you about the Chicago Warehouse record?
  • Where do the values shown here appear to come from, and does anything look inconsistent or unresolved?
  • Which of the things you see would you want to act on first, and why?
Task 2Open the discrepancy viewer
Say to participant Click Resolve to open the viewer. Once it's open, click around inside it — the documents, the sources, the values — and talk us through what you're looking at: what does this viewer show you, and how would you use it? Don't commit to anything yet — just explore and describe.

Path (researcher only): the Resolve Attribute Mapping card → Resolve, or the "Resolve" link on the detail panel's discrepancy banner. This opens the Select Source / View Sources viewer with the document canvas on the left and the source/value list on the right.

Follow-up questions
  • What is this viewer showing you? What are the different areas for?
  • How do the documents on one side relate to the values on the other?
  • What would you expect to do next in here? Rate 1–5
Task 3Resolve the ZIP Code conflict
Say to participant The ZIP Code for Chicago Warehouse was found on more than one document, and the values don't match. Review the sources, decide which one you'd trust as the correct ZIP, and select it.

Path (researcher only): Resolve Attribute Mapping → the ZIP Code row → Select Source; or click the Source cell on the ZIP Code attribute to open the Select Source viewer. The email source shows 60612 while the other documents show 60607 — pick a source using the radio buttons.

Follow-up questions
  • How did you decide which source to trust?
  • Was it clear that multiple documents disagreed on this value? Rate 1–5
  • How easy was it to choose a source? Rate 1–5
Task 4Map an attribute to Country
Say to participant Some extracted data hasn't been matched to a standard field yet — it's sitting as "unmapped." Still on Chicago Warehouse, map the relevant attributes to the Country field, then resolve the discrepancy so it no longer shows as unresolved.

Path (researcher only): View Sources → Unmapped tab → the Country row(s) → Map; or the "Associate Attribute" / "Map Attributes" control on the Country canonical-term row. Map every Country extraction, then use "Mark as Resolved" (or select the preferred source) so the Country discrepancy clears.

Follow-up questions
  • Did you understand the difference between a "mapped" and an "unmapped" attribute?
  • How confident are you that you mapped it to the right field? Rate 1–5
  • How easy was this task? Rate 1–5
Task 5Override a value
Say to participant Suppose the mapped State value is close but not quite right. Override it with your corrected value, then resolve the discrepancy so it no longer shows as unresolved.

Path (researcher only): the State attribute row has an inline Override Value cell — hover reveals a pencil; type a value and commit. An override clears the low-confidence flag; use "Mark as Resolved" if the discrepancy is still listed.

Follow-up questions
  • What did you expect "Override" to do, compared with picking a different source?
  • Was the difference between overriding and choosing a source clear? Rate 1–5
  • How easy was this task? Rate 1–5
Task 6Enter a manual value for Fire Alarm
Say to participant Now imagine that none of the extracted sources for Fire Alarm are usable, and you need to type the value in yourself. Enter a manual value for the Fire Alarm attribute on Chicago Warehouse.

Path (researcher only): the Fire Alarm canonical-term row offers a "[Map attributes]" / manual-value affordance; after entering a value the source reads "Manually edited" / "Manual".

Follow-up questions
  • Did the system make it clear that this value came from you, not from a document?
  • What do you understand to be the difference between entering a manual value and overriding a value? Open answer
  • How easy was this task? Rate 1–5
Task 7Save & review your changes
Say to participant You've made a number of changes to this record. Save your changes, then look back over the grid and find the attributes you changed — ZIP Code, Country, State, and Fire Alarm.

Path (researcher only): use the Save button in the pinned footer, then scan the attribute grid. Expect the participant to call out ZIP Code (source selected), Country (mapped + resolved), State (overridden), and Fire Alarm (manual value).

Follow-up questions
  • How easy was it to see which values you had changed and how? Rate 1–5
  • Looking at the grid now, is it clear where each value came from — a document, an override, or a manual entry?
  • Was anything about saving or confirming your changes unclear? Rate 1–5
Task 8Resolve a duplicate submission line
Say to participant The system flagged some submission lines that may be duplicates of each other. Click Resolve on the Resolve Duplicate Submission Lines card, review the flagged records for Location 3A – San Jose Manufacturing Campus side by side, and decide whether to merge them into one or keep them separate. Complete your decision.

Path (researcher only): Resolve Duplicate Submission Lines card → Resolve → compare the side-by-side cards for the San Jose Manufacturing Campus pair (Location 3A / 3B) → Select to Merge + Merge Selected, or Do Not Merge.

Follow-up questions
  • What information did you use to decide whether these were the same record?
  • How confident did you feel in your merge decision? Rate 1–5
  • Was anything about comparing the two records confusing?
  • How easy was this task? Rate 1–5

Wrap-up questions

Ask after all tasks are complete.

  • Overall, how confident would you feel that this submission is "clean" and ready to quote after doing this? Rate 1–5
  • What was the most confusing moment in the whole flow?
  • What was the most helpful thing the system did for you?
  • If you could change one thing about this reconciliation process, what would it be?
  • Overall, how easy or hard was the reconciliation process as a whole? Rate 1–5
